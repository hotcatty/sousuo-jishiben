给**人测**和**另一个 AI agent**一起用。产品设计层已经收束，这一轮只找具体问题：错位、漏交互、状态不一致、整理/收集逻辑不对。

## 1. 这是什么

Chrome MV3 插件。主战场是**小红书**。人自己搜、自己决定收什么；插件是这次搜索的记事本，不是聊天助手，也不替用户点网页。

典型闭环：

进站写目的 → 搜 → 收集帖子/评论/粘贴 → 侧栏整理成分区 → 按建议词再搜。

B 站 / 抖音脚本还在仓库里，**不是本轮主测对象**。除非顺手发现崩溃，不要把精力放在那里。

## 2. 加载与环境

1. Chrome → `chrome://extensions/` → 开发者模式 → **加载已解压的扩展程序** → 选插件根目录。
2. 扩展 ID 以本机为准（此前解压加载过的是 `gejhbdlplajgedgdbpohhjpgbmodinpm`，重装可能变）。
3. 每次改代码：**先点扩展卡片上的刷新，再刷新小红书页**。只刷网页不够。
4. 侧栏跟小红书走：在小红书会展开（闸门点完、收集、点工具栏、切回小红书标签）。切到别的网站应自动收起。点工具栏图标在小红书里也能开。
5. 登录一只有内容的小红书号。无登录很多笔记页打不开。
6. 设置里填 API Key（测「快速整理」必须有；只测收集可以暂时不填）。DeepSeek 能用，其它 OpenAI 兼容的 Key 也可以。
7. 本地预览页（不装插件也能看部分 UI）：  
   `python3 -m http.server 8766 --bind 127.0.0.1`（在插件根目录）  
   - 闸门 / 猜测无关 / 收集胶囊：`http://127.0.0.1:8766/eval/browse-preview.html?state=gate|filled|focus|guess|collect|toast`  
   - 侧栏壳：`http://127.0.0.1:8766/src/pages/_harness.html`  
   - 设置页：`http://127.0.0.1:8766/src/pages/_harness.html?sheet=settings`

README 里有些旧描述（页内嵌记事本、OCR 划选）已经过时，**以本文和当前代码为准**。

## 3. 产品规则（对错的判据）

测的时候用这些当预期，不要按「常见笔记软件」脑补。

### 3.1 收集箱 vs 分区 tab

| | 收集箱 | 用户/AI 新建的分区 |
|---|---|---|
| 一键收集（帖子与评论、点点回答） | **一定进这里** | 不进 |
| 在当前 tab 粘贴/拖入图文 | 只进收集箱 | **当前分区立刻能看见，同时同步进收集箱** |
| 角色 | 全部原文的总和 | 会被 AI 读到、整理、改写成分区卡片 |
| 空状态文案与位置 | 居中：「粘贴图片或文字到这里」 | **同一句、同一居中样式**，不要再用「还没有整理进这一块的内容」顶在上面 |

### 3.2 顺序

- 最新添加的在**最上面**，旧的在下面。
- 快速整理之后，已整理的原文**置灰**（`opacity 0.45`）。
- 新收、还没整理、没置灰的，必须压在置灰内容上面。

### 3.3 页面收集

- 打开笔记详情（左图右文那种）：搜索模式下若判定跑偏，左侧图上出现「猜测无关」条，位置在点赞/评论/「说点什么」底栏**上方**，贴在图片上，不要压住底栏，也不要锚到背后信息流。
- 未跑偏时：右侧栏、底栏上方出现「收集帖子与评论」。点了立刻开侧栏，**不要成功 Toast**。同一篇笔记不要重复收。
- 「猜测无关」和「收集」不同时出现。点「有关，我自有考虑」后，应收起猜测条并允许收集。

### 3.4 闸门与专注

- 进小红书**第一次**先出闸门：目的输入 + **搜一搜** / **随便逛逛**。
- 搜一搜 → 搜索模式（专注开），去搜这个词。
- 随便逛逛 → 浏览模式。关专注 ≈ 插件拦截关掉：不再出入口闸门「咱来搜点什么」，切首页 / RED / 直播也不出拦截卡「专注模式，咱先不开小差」。笔记上的收集胶囊可以留着。
- 「随便逛逛」本身是进浏览的入口，不要拦、不要当成违规。
- 浏览静默存在后台 `chrome.storage.session` 键 `fg_xhs_browse_silence`（跨标签共享，不是每页自己的 `sessionStorage`）：只要还有**任意**小红书标签开着，新开的小红书标签（搜索页、收藏等）也不出闸门、不出拦截卡。
- 关掉**所有**小红书标签后，静默清掉。下次再进当作第一次，再出目的闸门。
- 侧栏顶栏「专注模式」开关 = `SET_PRODUCT_MODE` 搜索 / 浏览（不是设置里的 focusMode auto/on/off）。
  - 关掉：所有小红书标签立刻藏闸门、藏拦截卡。
  - 再打开：这次已有目的/关键词就直接进搜索（该拦的栏目会拦）；没有目的就再出入口闸门。
- 设置页只有两块：**拦截频道**（开关）和 **API Key**。不再有自动/开启/关闭三段。
- 拦截频道默认开：首页、RED、直播。默认关：点点、发布、通知、消息、我的。开关立刻生效。
- 现阶段只适配小红书。B 站 / 抖音以后再说。
- API Key：不限定 DeepSeek。填完失焦或回车即保存并试连。感叹/信息 icon 悬停说明「接上大模型后，整理和搜索推荐会更准。」下面「主流 AI 大模型 API 申请指南」目前没有跳转。
- 被拦截时关掉专注开关，**当前拦截卡应立刻消失**。
- 开关 Toast 出现在**小红书页面下方**（不是侧栏里）：开 = `切换到` + 实际会拦的栏目名 + `会被拦截`；关 = `你可以随便逛了`。

### 3.5 整理

- 「快速整理」只在收集箱、且有未整理原文时出现。
- 整理后原文仍留在收集箱（置灰），分区里是派生卡片。
- 用户改过的卡片应被视为冻结，AI 再整理不该乱改乱删（有 Key 时才测得动）。
- 分区里的删除、卡片展开/收起、「单击删除」胶囊不要漏字到按钮周围。
- **按真实主题拆 tab**，不要把一篇混着的笔记全倒进同一个分区。例：月全食应收成「月全食时间 / 地点 / 参数」；旅游常见「路线 / 美食 / 居住」。
- 板块名短、像 tab。不要生成一篇完整攻略正文；仍然是搜索记事本。
- 无 Key 时走本地规则，有小标题（时间、地点、拍摄参数等）也应拆开。有 Key 时模型提示同样要求拆 `new_boards`。

### 3.6 点点

- 打开点点后，应用本次搜索词**自动填进点点输入框**（不要把词反复拼在后面）。
- 「收集点点回答」胶囊在**回答出现之后**才显示，不要在空白输入态就浮着。
- 位置对照 Figma `58:2844`：白底胶囊「收集点点回答」，铺在点点侧栏回答区上，水平居中，距面板可见底约 14px。不要复活「收这张图 / 框选文字」。
- 点了把回答收进收集箱。点点还没吐内容时允许 Toast「点点还没给出内容」。
- 若点点回答画在 **closed shadow DOM** 里，内容脚本读不到正文、也无法稳定锚点：记 **blocker**（DOM 证据：有没有 light DOM 的「ai总结 / 篇笔记生成」、输入框 placeholder），不要判成产品不做、也不要为此去 hook 页面内部脚本。

### 3.7 不要再测的旧能力

已砍，出现反而是回归：闲时监控气泡、搜这张图 / 收这张图、框选文字 OCR、收集成功 Toast、加号上的「新建分区」提示。鼠标移到笔记图上不得再出「收这张图」「框选文字」两颗胶囊。

### 3.8 侧栏跟页走

- 小红书（含闸门页、搜索、笔记）：侧栏应打开。闸门点完、收集、工具栏图标都会打开。
- 用户**主动关掉**侧栏后，点任何提醒按钮都应再打开：闸门「搜一搜/随便逛逛」、拦截卡「继续搜索」和推荐词、猜测条「回到搜索 / 有关」、收集帖子、收集点点。点完再跳搜索页，右侧仍应有记事本（计时轮）。
- 切到**不是小红书**的网页或标签：侧栏应自动收起。
- 再切回小红书：侧栏应再打开。切标签算用户手势，一般能开；若某版 Chrome 拦了自动打开，切回后点工具栏仍应能开。

### 3.9 推荐搜索词（小红书）

- 词要短、自然，像人打进搜索框：`广州美食`、`广州塔预约`。不要用空格堆地点或百度式操作符。
- 不要原样重复用户正在搜的整句目的。
- 两类：方向提醒（旅游常见：美食 / 路线 / 预约，材料里缺哪条补哪条）；细节补充（材料里已有的具体点，还缺预约等信息）。
- 明显跑题的词（和这次目的对不上）不应出现。本轮不要求直接生成完整攻略。

**D. 侧栏收集箱**

- [ ] 空状态居中「粘贴图片或文字到这里」
- [ ] 粘贴一段文字、再粘贴一张图，都出现在列表**顶部**
- [ ] 点开长卡片，删除胶囊周围没有漏字

**E. 分区**

- [ ] 点收集箱旁 `+`，能新建分区（加号不要再出提示）
- [ ] 空分区空状态与收集箱一致
- [ ] 在空分区粘贴：当前分区看得到，切回收集箱也能看到同一条原文
- [ ] 一键收集仍只进收集箱，不会进当前分区

**F. 整理**

- [ ] 有 Key 时快速整理能出分区和卡片

- [ ] 旅游材料常见拆成路线 / 美食 / 居住（有哪类出哪类）

- [ ] 再粘贴新内容：新的在最上面且不置灰，旧的置灰在下面
- [ ] 双击分区名可改名；删分区后原文还在收集箱

**G. 专注**

- [ ] 搜索模式下进首页/RED/直播会出拦截卡
- [ ] 消息/通知/发布/我的默认不拦

- [ ] 再打开专注，Toast 文案带上会拦的栏目名

- [ ] 拦截卡上的推荐词是短词（无一长串空格），点词同样会打开侧栏并去搜
- [ ] 设置页：返回字重偏细；拦截频道是开关清单；默认首页/RED/直播开，点点等关
- [ ] 关掉「首页」后再进首页，不应再出拦截卡

## 5. AI agent 怎么测

### 5.1 角色

你是 QA，不是产品改版。默认**只报问题、不改代码**，除非用户明确说「顺手修」。

### 5.2 怎么跑

1. 读本文件 + `manifest.json` + `src/pages/panel.js` + `src/content/xiaohongshu.js` + `src/content/xhs-ui.js`。不要用过期 README 当预期。
2. 确认扩展已加载 **1.31.0**。没加载就按第 2 节加载，不要另起一个仓库。
3. 真机优先：打开 https://www.xiaohongshu.com 走 A–G。闸门/胶囊可用 `eval/browse-preview.html` 做位置对照，**不能替代**真站。
4. 需要登录、验证码、或点点打不开时：**停，写 blocker**，不要硬刷。
5. 不要用内容脚本去「模拟点击收集」当唯一证据；以用户能看见的 UI 为准。
6. 不要输出 exploit / 绕过登录 / 抓 cookie。

### 5.3 建议顺序（约 40–60 分钟）

1. 品牌与侧栏能否打开  
2. 闸门搜一搜 / 随便逛逛  
3. 相关笔记收集 + 去重 + 无 Toast  
4. 跑偏笔记猜测条位置  
5. 粘贴顺序与空状态  
6. 新建分区粘贴双写（分区 + 收集箱）  
7. 快速整理：主题拆 tab（月全食 / 旅游）+ 置灰 + 新内容置顶（有 Key）  
8. 首页拦截与开关 Toast；闲逛跨标签不出闸门  
9. 点点回答后的收集胶囊（可选，shadow DOM 则记 blocker）

本地 harness 可辅助：空侧栏、整理后卡片、删除漏字。发现 harness 和真插件不一致，以真插件为准。

### 5.4 报告格式

每个问题一条：

```
### [P0/P1/P2] 短标题
- 环境：Chrome 版本 / 插件 1.31.0 / 是否有 Key / 是否登录
- 步骤：
- 预期：
- 实际：
- 证据：截图或录屏路径
- 是否必现：
```

优先级：

- **P0** 收不进、侧栏打不开、整理把原文弄丢、拦截关不掉
- **P1** 位置明显错、顺序反了、空状态错、重复收集、Toast 跑到侧栏
- **P2** 动效、文案微调、点点填词失败（记录 DOM）

最后加一节：**本轮没测到的**（例如没开点点、没 Key）。

不要把「和 Figma 差 2px」写成 P0。位置以设计稿相对关系为准：猜测条在底栏上方、收集在右栏底栏上方、空提示居中。

## 7. 已知脆点（先对照再开 bug）

- 点点自动填词依赖页面输入框，小红书一改 placeholder / 受控组件就可能失败。
- 点点回答若在 **closed shadow DOM** 内：读不到「ai总结」正文，收集胶囊锚不到回答区。先记 DOM，不要当普通 UI 错位。
- 笔记层 DOM 经常变：收集/猜测条若锚到信息流而不是弹层，是 P1。
- 无 API Key 时「快速整理」走本地规则；能按小标题拆 tab，文案质量差不算 UI bug。
- 切到非小红书标签必须收起侧栏。切回后自动打开依赖 Chrome 是否把切标签当成用户手势；打不开但点工具栏能开，记 P2。
- `docs/PRD.md` 和部分 demo 文案可能落后于 1.31.0。
